# NetScope

أداة مفتوحة المصدر لفهم استهلاك الإنترنت المشترك وتقسيم التكلفة حسب الاستخدام.

**الحالة الحالية: أساس React/Tauri جاهز للتطوير، وليس تطبيق قياس مكتملًا.**
توجد واجهة أولية تعرض القيم غير المعروفة، ومكوّن Arc مجاني فعلي، وAPI للصحة
فقط. القياس والخدمات الأصلية والمشاركة والحسابات المالية لم تُنفّذ بعد.

## الستاك المعتمد

- واجهة واحدة: React DOM وTypeScript وVite، للموقع وللتطبيقين.
- Tauri 2 لاستضافة الواجهة المضمّنة على Windows وAndroid.
- مكوّنات Arc المجانية المتوافقة مع shadcn، وTailwind CSS 4 وLucide وMotion.
- خدمة Rust مستقلة لقياس Windows، وطبقة Kotlin عبر إضافة Tauri لقياس Android.
- SQLite محليًا، وRoom على Android.
- لاحقًا: Hono على Cloudflare Workers وD1/Drizzle وBetter Auth بعد اختبار التوافق والحدود المجانية.

اختير React DOM للاستفادة من Arc مباشرة. قرار الستاك الحالي موثّق في
[سجل القرار](docs/decisions/0002-react-tauri.md). المتصفح يعرض الواجهة والتقارير
فقط؛ لا يستطيع قياس استهلاك الجهاز كله.

## التشغيل

ثبّت Node 24 ثم نفّذ من جذر الريبو:

```sh
npm ci
npm run dev:client
```

لتشغيل مضيف Windows، ثبّت Rust وأدوات MSVC C++ وWebView2 ثم:

```sh
npm run tauri --workspace @netscope/client -- dev
```

التفاصيل والاختبارات ومتطلبات Android في [دليل التطوير](docs/DEVELOPMENT.md).

## مسار الإطلاق

1. نسخة Windows محلية مفيدة: تحديد الشبكة، قياس حقيقي موصوف الدقة، حفظ وسجل وفجوات وتصدير ومثبّت.
2. المشاركة: حسابات وسكن وأجهزة متعددة ومزامنة موثوقة وموقع React مشترك.
3. تقسيم كامل التكلفة بنسبة الاستخدام المقبول، لفترة بداية ونهاية يحددها المستخدم، ومراجعة البيانات المفقودة.
4. إصدار Android على الأجهزة التي تثبت اختبارات النظام إمكانية دعمها.

لا نحتاج صلاحية الراوتر أو VPN أو root أو Student Pack أو استضافة مدفوعة إلزامية.
النظام تعاوني: حذف التطبيق أو إيقافه قد يترك فجوات لا يمكن تفسير سببها عن بُعد.
الفجوة ليست صفرًا، وعداد Wi-Fi قد يشمل حركة محلية لا تخص باقة الإنترنت.
